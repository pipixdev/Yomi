# 阅读器性能排查与优化

本次保持整体界面、字体、分页参数、章节结构及已有书签格式不变。以下结论来自源码检查与回归测试；没有进行 Instruments 真机采样，也没有用模拟 DOM 的耗时推算设备上的帧率。

## 已处理的热点

| 路径 | 原有问题 | 改动 |
| --- | --- | --- |
| 阅读进度 | 每次位置回调在主线程编码整个书库、原子写盘，并分别修改两个 `@Published` 数组字段 | 重复位置直接跳过，合并成一次状态发布；后台串行编码／写盘，每秒合并一次；关闭和进入非活动状态时立即提交 |
| 数据持久化顺序 | 将进度写入简单改为异步会引入旧快照覆盖删除／重建的风险 | 进度和原有书库操作共用串行写入队列，保留 ISO-8601 日期与原子写入，错误会回传；失败的最新进度保留为待保存状态 |
| 阅读器退出 | 阅读器持有 navigator，WebKit 内容控制器强持有阅读器作为消息处理器，形成引用环 | 使用弱引用消息代理；保存并取消加载任务，取消后不再创建／嵌入阅读器；SwiftUI 拆卸也取消加载 |
| 点击长章节段落 | 每次重建全章数组；每个段落分别扫描同级兄弟来计算 CSS selector，平铺章节呈平方级增长；主线程为全章生成书签 JSON | 缓存章节索引和桥接数据，按父节点复用兄弟位置；DOM 结构变化后失效；原生侧只生成当前段落的书签 JSON |
| 打开／切换解析 | 主线程初始化 MeCab 和同步分词，可能阻塞导航及拖动回调 | 独立 actor 懒初始化并串行分词；任务取消与索引校验避免旧结果覆盖；有界缓存加速往返阅读，加载时使用系统进度指示 |
| 朗读高亮 | 每次高亮重新拼接整段 HTML、执行 ruby 对齐，再比较 HTML 是否变化；JS 每次扫描全部词元 | 先比较词元／字号，变化时才生成 HTML；缓存 DOM 和 UTF-16 偏移，二分定位重叠区间，仅修改变动样式；相同高亮不跨桥调用 |
| 解析布局 | 每次 SwiftUI 更新（包括高亮）都强制失效 intrinsic content size | 继续使用 iOS 16 的 hosting intrinsic sizing，让内容尺寸变化驱动布局 |
| 书架后台刷新 | 阅读进度广播引起书卡重新求值时，会再次从磁盘读取封面 | 单独的 Equatable 封面视图，以 URL、标题和导入时间作为输入；进度和翻译菜单仍正常更新 |
| 资源路径 | 状态更新重新计算阅读器／封面 URL 时，重复向 FileManager 查询 Application Support | 复用初始化时已确定的 manifest 所在目录 |

分词缓存最多保留 16 段、共 12,000 个词元，单段超过 256 KB 或 12,000 词元则不加入缓存；当前正在显示的段落不受此限制。分词器仅在其 actor 内使用，避免同时访问非线程安全的 MeCab 实例。

## 验证

- XcodeBuildMCP：`Yomi.xcodeproj` / `Yomi` / iPhone 17，iOS Simulator 编译。
- JavaScript：执行源码中实际注入的脚本，验证 3000 段的 selector、日文／emoji、书签索引、返回定位、重复点击复用、DOM 插入后的缓存失效，以及链接／选区／键盘交互。
- 3000 个平铺段落的首轮 selector 构建访问 6002 个兄弟节点；旧实现会对每个段落重新扫描 6000 个同级元素，仅这一层就需要约 1800 万次元素访问。重复点击复用索引和 selector，但跨 WebKit 桥传输整章文本的成本仍存在。
- 高亮：10000 个词元，检查首尾、跨词元、零长度、越界和清除高亮；DOM 查询只执行一次。
- 持久化：150 次排队写入、进度最终值、删除／重建顺序、Unicode 和日期往返、失败回传以及原有文件保持完整。测试的是实际 writer 和数据模型，未替换为测试版本。
- 未新增用户可见文案；沿用现有字符串目录、翻译／词典设置及现有中英文无障碍标签。新增的加载反馈使用系统 `ProgressView`。

可重复运行：

```sh
node Tests/reader-script-checks.mjs
swiftc -parse-as-library Yomi/Models.swift Yomi/LibraryManifestWriter.swift Tests/ReaderPersistenceChecks.swift -o /tmp/yomi-reader-persistence-checks
/tmp/yomi-reader-persistence-checks
```

Swift 检查是 Foundation 持久化组件的宿主机测试，不是 macOS App 验证；应用平台验证保持 iOS 优先。

## 边界与后续采样重点

- 一秒检查点意味着异常崩溃／强制终止可能丢失最后约一秒以及尚未写完的进度；正常退出和进入后台会主动提交。系统后台时间有限，磁盘失败或直接强杀仍无法保证写入完成。
- 导入、重建、删除等低频操作继续等待持久化结果，以维持原来的错误处理行为；它们也可能等待之前排队的写入。高频翻页不等待该队列。
- Readium 的超长单章分页、ruby 排版和 WebKit 峰值内存仍需用真实大书在设备上采样。未盲目提高预加载量，也未切割章节，以免增加内存或破坏已有定位。
- 解析视图切换段落时仍保留既有 WebView 重建方式；下一步可用 Allocations/Time Profiler 确认它相对于分词和排版的实际占比，再考虑跨段落复用。
- 并行整书翻译仍会发布书库状态。本次移除了封面重读及高亮 HTML 重建等连带成本；如运行中仍有卡顿，应同时采样网络回调、翻译缓存 I/O 与 UI 更新频率。
- 为 Xcode 默认执行的 App Intents 元数据提取步骤补充系统框架 import，消除缺少框架依赖的构建警告；没有增加 App Intent、快捷指令或第三方依赖。
