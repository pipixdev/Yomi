# 阅读器性能排查与优化

本次保持整体界面、字体、分页参数、章节结构及已有书签格式不变。以下结论来自源码检查与回归测试；没有进行 Instruments 真机采样，也没有用模拟 DOM 的耗时推算设备上的帧率。

## 已处理的热点

| 路径 | 原有问题 | 改动 |
| --- | --- | --- |
| 阅读进度 | 每次位置回调在主线程编码整个书库、原子写盘，并分别修改两个 `@Published` 数组字段 | 重复位置直接跳过，合并成一次状态发布；后台串行编码／写盘，每秒合并一次；关闭和进入非活动状态时立即提交 |
| 数据持久化顺序 | 将进度写入简单改为异步会引入旧快照覆盖删除／重建的风险 | 进度和原有书库操作共用串行写入队列，保留 ISO-8601 日期与原子写入，错误会回传；失败的最新进度保留为待保存状态 |
| 阅读器退出 | 阅读器持有 navigator，WebKit 内容控制器强持有阅读器作为消息处理器，形成引用环 | 使用弱引用消息代理；保存并取消加载任务，取消后不再创建／嵌入阅读器；SwiftUI 拆卸也取消加载 |
| 点击长章节段落 | 每次重建全章数组；每个段落分别扫描同级兄弟来计算 CSS selector，平铺章节呈平方级增长；主线程为全章生成书签 JSON | 缓存章节索引和桥接数据，按父节点复用兄弟位置；DOM 结构变化后失效；原生侧只生成当前段落的书签 JSON |
| 打开／切换解析 | 主线程初始化 MeCab 和同步分词，可能阻塞导航及拖动回调 | 独立 actor 懒初始化并串行分词；任务取消与索引校验避免旧结果覆盖；有界缓存加速往返阅读，加载时使用系统进度指示 |
| 朗读高亮 | 每次高亮重新拼接整段 HTML、执行 ruby 对齐，再比较 HTML 是否变化；JS 每次扫描全部词元 | 先比较词元／字号，变化时才生成 HTML；缓存 DOM 和 UTF-16 偏移，二分定位重叠区间，仅修改变动样式；相同高亮不跨桥调用 |
| 解析布局 | 每次 SwiftUI 更新（包括高亮）都强制失效 intrinsic content size | 继续使用 iOS 16 的 hosting intrinsic sizing，让内容尺寸变化驱动布局 |
| 书架后台刷新 | 阅读进度广播引起书卡重新求值时，会再次从磁盘读取封面 | 单独的 Equatable 封面视图，以 URL、标题和导入时间作为输入；进度和翻译菜单仍正常更新 |
| 资源路径 | 状态更新重新计算阅读器／封面 URL 时，重复向 FileManager 查询 Application Support | 复用初始化时已确定的 manifest 所在目录 |

分词缓存最多保留 16 段、共 12,000 个词元，单段超过 256 KB 或 12,000 词元则不加入缓存；当前正在显示的段落不受此限制。分词器仅在其 actor 内使用，避免同时访问非线程安全的 MeCab 实例。

## 边界与后续采样重点

- 一秒检查点意味着异常崩溃／强制终止可能丢失最后约一秒以及尚未写完的进度；正常退出和进入后台会主动提交。系统后台时间有限，磁盘失败或直接强杀仍无法保证写入完成。
- 导入、重建、删除等低频操作继续等待持久化结果，以维持原来的错误处理行为；它们也可能等待之前排队的写入。高频翻页不等待该队列。
- Readium 的超长单章分页、ruby 排版和 WebKit 峰值内存仍需用真实大书在设备上采样。未盲目提高预加载量，也未切割章节，以免增加内存或破坏已有定位。
- 解析页后续已改为单 WebView 连续滚动，见下方重构说明；长段落的 WebKit 排版、惯性滚动和旋转仍需要真机采样。
- 并行整书翻译仍会发布书库状态。本次移除了封面重读及高亮 HTML 重建等连带成本；如运行中仍有卡顿，应同时采样网络回调、翻译缓存 I/O 与 UI 更新频率。
- 为 Xcode 默认执行的 App Intents 元数据提取步骤补充系统框架 import，消除缺少框架依赖的构建警告；没有增加 App Intent、快捷指令或第三方依赖。

## 打开书籍前的无反馈等待

后续修复了“点击后仍停留在书库，加载指示尚未出现”的呈现间隙：

- 书架／书签点击立即设置选择状态，事件处理器拒绝重复选择，整个入口导航区域禁用。后续消除了入口独立遮罩：选书事务关闭入场动画，直接呈现阅读器外框（最新实现仅显示 Readium 自带的正文加载动画，见文末）。弹出阅读器仍挂在入口禁用修饰器之外，避免连返回按钮一起禁用。
- `viewDidLoad` 只创建轻量加载视图，实际加载放到首次 `viewDidAppear`；返回解析页面时不会重复打开书籍。不依赖固定延时或 `Task.yield()` 来猜测界面是否已出现。
- Readium runtime 改为懒创建；本应用只打开 EPUB，直接使用 `EPUBParser`，减少不需要的其他格式解析器初始化。没有改变正文、位置算法、预加载参数或存储格式。
- 加载覆盖层保留到 Readium 首次报告稳定阅读位置；此回调由当前依赖在导航 idle 状态、初始 spread 加载后触发。仅创建 navigator 不再视为加载完成。
- 加载期间正文不可点击，返回按钮仍可退出。初始章节资源读取失败会结束转圈并显示错误；邻章预加载和附属资源错误不用于判定首章失败。

验证：XcodeBuildMCP / Yomi / iPhone 17，编译成功且日志无 warning/error；核对现有中英文加载文案。此轮按项目默认执行编译验证，没有进行设备交互或耗时采样，因此不将呈现时序修复描述为长书总加载时长的量化提升。

## 解析页连续滚动重构

- 移除边缘拉动切段、内嵌 `UIScrollView` 和单段 WebView 高度回传，整章共用一个原生滚动 WebView。书签、翻译、朗读按钮位于各段原文下方，译文在按钮之后自然排版。重复点击书签取消收藏；重复点击翻译取消请求或收起译文。
- 整章只预建轻量高度占位，活动区域包含可见段落及前后各六段，最多 33 段；离开范围后释放词元 DOM、段落任务及原生状态。保留测得高度避免回滑时塌陷。章节文本和占位节点仍随章节长度线性增长；单个异常长段落仍需要完整分词和排版。
- 后台 actor 完成 MeCab 分词、ruby 对齐和 HTML 生成。缓存共用 16 段 / 12,000 词元预算；一个词元只执行一次 ruby 对齐。首屏优先请求，离开范围取消任务，窗口代次和翻译请求 ID 拒绝旧结果。
- 译文插入、收起及分词结果同帧合并更新；通过第一可见段落的屏幕位置补偿上方高度变化。滚动帧以二分查找定位段落，不扫描整章词元，只有当前段落变化才更新 SwiftUI 标题和返回阅读定位。
- 同一解析页只创建一个朗读控制器；高亮直接跨桥更新对应段的缓存词元索引，不触发 SwiftUI 重建。朗读段移出活动窗口时停止。
- 翻译显隐偏好在本次解析会话保留，重新进入已收起的段落不会被磁盘缓存自动展开；重新显示复用原有翻译缓存。共享译文内存缓存新增 128 条 / 1 MiB UTF-8 文本预算，淘汰不影响磁盘持久化或整书翻译的断点恢复。
- 保留系统/外部词典、注音、词性颜色、浅深色和解析字号设置。新增“收起译文”中英文文案；HTML 按钮的名称及开关状态使用本地化可访问属性。

## 进入解析页后目标段落被挤走

原实现仅在首次进入时执行一次 `scrollIntoView`，随后根据临时可见位置选择锚点。章末内容不足一个屏幕时，浏览器还会限制滚动范围；后续的字体/ruby 排版或视口调整不在原来的 DOM 更新补偿范围内。

- 进入时固定使用点击段落作为锚点，保持距导航安全区域顶部 16 CSS px 的原有内容留白。初始分词、缓存译文、文档尺寸及视口变化都会复用这一锚点，不再从已经偏移的位置重新选段。
- 章末加入足够的底部留白，使最后一个短段也能放到顶部。
- 原生 WebView 关闭重复的自动 content inset 调整，由 SwiftUI 安全区域负责导航栏布局。
- 用户触摸、滚轮、滚动键、原生拖动或点击状态栏回顶后解除初始锁定，恢复连续滚动；文档 ResizeObserver 仅在锁定期间按帧合并校正，不使用延时轮询。
- 新增回归覆盖真实滚动范围上限、1/3/8/3000 段中的章末进入、乱序加载、缓存译文、延迟字体布局、视口变化与用户接管滚动；沿用中英文按钮文案，没有新增用户可见字符串。

本轮验证结果：脚本回归通过，iPhone 17 模拟器编译通过且无编译警告。真机 Debug 编译和签名也通过；MCP 的 CoreDevice 安装阶段无法识别 iOS 16 的 iPhone X，随后改用 Homebrew `ios-deploy` 完成 USB 安装并保留命令行 LLDB 会话，独立 `--get_pid` 查询确认 `com.pipix.Yomi` 正在运行。安装覆盖保留现有 App 数据。没有使用截图验证页面位置。

后续真机流程保持命令行：MCP 构建签名后的 `Debug-iphoneos/Yomi.app` → `ios-deploy --debug --noninteractive --id <UDID> --bundle <App路径>` → `ios-deploy --get_pid --bundle_id com.pipix.Yomi --id <UDID>`。这台设备不使用 MCP 的 CoreDevice 安装通道，不使用 Computer Use。保留调试会话时不要加 `--timeout`，该参数也会限制 App 运行时长。

## 合并开书加载提示

检查原始修复后保留其目的：点击即反馈、防止重复打开、慢书加载不阻塞入口呈现，并允许加载中退出。书架和书签入口现在只改变选择状态与交互权限，选择事务禁用入场动画，直接显示阅读器的轻量加载页，不再经历“入口半透明转圈 → 阅读器转圈”两次切换。关闭阅读器的既有过渡未全局禁用。

耗时流程仍仅在首次 `viewDidAppear` 发起，Readium runtime 仍然懒创建；只有首个稳定阅读位置回调才移除原生加载遮罩，初始资源错误结束转圈并显示错误，退出仍取消任务并保存进度。改动复用原有中英文加载提示，无新增 UI 文案。验证边界：源码时序核对和 iOS 编译，不将其描述为实际加载耗时缩短或已进行截图验证。

## 进一步移除 Readium 前方的自建加载画面

源码确认仍存在两个独立的指示器：应用的 `UIActivityIndicatorView(.large)` 加文字，以及依赖 `EPUBSpreadView` 内居中的 `.medium` 指示器。此前仅去掉书架入口遮罩，未移除前者，因此不能据此声称只剩一套加载动画。

最新实现删除应用的 spinner、全屏 loadingOverlay 和对应布局，仅保留 Readium 自带的正文加载动画。点击直接呈现带返回按钮的同一个阅读器外框；打开 publication 的短暂阶段没有额外转圈，创建并嵌入 navigator 后直接显示其正文加载动画。没有人为等待、没有提前隐藏 Readium 转圈，也没有修改依赖私有视图。

原有保护继续保留：两个入口同步设置选择状态并拒绝重复选择、入口禁用、无入场动画、首次 `viewDidAppear` 才执行一次加载、runtime 懒初始化、首个稳定位置前正文不可交互、关闭取消任务和保存进度、初始化或初始章节资源失败显示错误。保留错误文案和现有本地化；删除的额外加载文字不会由英文文本替代。


## 退出后快速再次开书的交互恢复

书架和书签原本在进入时直接写入选择状态、关闭入场动画，但退出在原生返回结束后调用 SwiftUI 环境 `dismiss()`，再由系统回写选择绑定；列表禁用和重复点击保护仍依赖该绑定，外层退场也没有关闭动画。

现在 `ReaderView` 将关闭事件显式回传给入口，由入口在同一个禁用动画的事务中清除自己的选择状态。原生返回完成后不再附加一段外层模态动画，列表禁用与选书保护随同一状态恢复。保留原生返回与左边缘侧滑；关闭事件仍仅在 dismissal root 的 `viewDidAppear` 触发，因此取消侧滑不会提前清空选择。解析页返回只弹出解析页，不触发关闭。两个入口继续拒绝打开期间的重复选择；退出仍取消加载并异步提交进度，没有新增等待、轮询或用户可见文案。

验证范围：iOS Simulator 和真机 Debug 编译、命令行安装与运行；不将源码时序检查或编译结果视为已完成真机快速连点的交互复现。


## 原生封面菜单与阅读器呈现

真机日志确认了此前卡死的原因：菜单打开后点击封面，UIKit 报告宿主已经在显示 `_UIContextMenuActionsOnlyViewController`，拒绝呈现阅读器；原有选书状态却已写入并禁用了书架。仅将 `Menu` 移到开书按钮外不足以解决系统菜单退场期间的事件竞争。

最新实现使用 `BookActionsMenu` 桥接原生 `UIButton + UIMenu`，删除临时自定义的 `BookActionsOverlay`、遮罩、anchor preference 和 `Layout`。菜单位置、动画、动态字号、辅助功能和外部点击取消交给 UIKit；翻译、取消翻译、重建、删除采用 `UIAction`，危险操作使用系统 destructive 样式。非 iOS 分支使用 SwiftUI `Menu`。

- `BookshelfInteraction` 保留浏览／菜单／阅读三个互斥状态。`willDisplayMenuFor` 进入菜单状态，封面点击在菜单显示和整个退场动画期间均不能开书。
- `UIAction` 只记录待执行操作，`willEndFor` 中通过系统 animator 的 `addCompletion` 完成状态恢复并执行动作。删除确认不会与尚未退出的菜单竞争呈现；无动画时使用同步完成路径，无固定延时或轮询。
- 保留对 `super` 的生命周期调用，控件移除时请求 UIKit 关闭菜单。旧书籍关闭回调不能关闭另一本书，重复动作仅执行一次。
- 菜单仅在 UIKit 请求配置时从最新翻译／导入状态创建，常规翻译进度更新只刷新轻量回调，不重建菜单项。UIAction 标签继续使用中英文字符串目录。
- 书架不使用整页 `.disabled` 或自定义命中遮罩。阅读器的加载、原生返回／侧滑和进度保存流程不变。

接口依据：[UIControl 菜单生命周期](https://developer.apple.com/documentation/uikit/uicontrol/contextmenuinteraction)、[系统菜单动画完成回调](https://developer.apple.com/documentation/uikit/uicontextmenuinteractionanimating)。
